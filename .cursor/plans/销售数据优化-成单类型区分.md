# 销售数据优化 - 成单类型区分

## 修改概述
将 teachers/dashboard 的销售数据中的成单信息从成单信息表（conversions）抓取,并对续费成单和新签成单做出区分。

## 修改文件

### 1. `/greatstart/frontend/src/services/memfireDB.ts`

#### 修改位置：`getSalesStatistics` 方法（约第1836-1863行）

**修改内容：**
- 在查询 conversions 表时,添加了 `courseType` 字段的获取
- 将成单数据按 `courseType === '续费'` 进行分类
- 新增返回字段:
  - `renewalOrderCount`: 续费成单数
  - `renewalOrderAmount`: 续费成单金额
  - `newOrderCount`: 新签成单数
  - `newOrderAmount`: 新签成单金额

**代码变更：**
```typescript
// 查询时增加 courseType 字段
.select('id, price, courseType')

// 区分续费和新签
const renewalOrders = orders?.filter(order => order.courseType === '续费') || [];
const newOrders = orders?.filter(order => order.courseType !== '续费') || [];

// 计算续费数据
const renewalOrderCount = renewalOrders.length;
const renewalOrderAmount = renewalOrders.reduce((sum, order) => sum + (order.price || 0), 0);

// 计算新签数据
const newOrderCount = newOrders.length;
const newOrderAmount = newOrders.reduce((sum, order) => sum + (order.price || 0), 0);
```

## 数据来源

### 成单信息表（conversions）
所有成单数据都从 `conversions` 表获取,该表记录了所有的成单信息,包括：
- 新报名成单（`courseType !== '续费'`）
- 续费成单（`courseType === '续费'`）

### 数据分类逻辑
- **续费成单**: `courseType` 字段值为 `'续费'`
- **新签成单**: `courseType` 字段值不为 `'续费'`（包括 null 或其他值）

## 注意事项

1. 成单数据完全依赖于成单信息表（conversions）的 `courseType` 字段
2. 续费成单的判断标准是 `courseType === '续费'`
3. 所有非续费类型的成单都被归类为新签成单
4. 表格宽度已调整,如果列数继续增加,可能需要进一步优化布局
